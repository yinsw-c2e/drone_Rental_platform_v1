# 小程序 P1 冻结验收记录

## 目标

冻结小程序双入口主流程：

- `我要吊运`：客户发布、选方案、订单跟踪。
- `我要接单`：服务商入驻、接单、报价、主体自履约、结算入口。

本轮不验收 App，不验收 Web/管理端 UI。后台字段中的 `owner/pilot/dispatch` 继续作为兼容模型保留，但小程序用户可见主流程不再展示第三端表达。

## 自动门禁

静态冻结检查：

```bash
cd mini-program
npm run check:p1-freeze
```

完整冻结检查：

```bash
cd mini-program
RUN_BUILDS=1 npm run check:p1-freeze
```

业务闭环检查：

```bash
cd backend
PREPARE_DEMO_DATA=1 ./scripts/mini_program_p0_acceptance.sh
```

## 通过标准

- 小程序源码中不出现用户可见旧三端表达：`飞手 / 机主 / 执行人员 / 派单 / 协作 / 自执行`。
- 历史多人确认和历史人员关系页面只显示降级提示，不再调用旧列表、创建、详情、绑定接口。
- 设计图静态业务数据不进入生产页面，例如固定公司名、固定订单号、固定金额。
- `npm run build:weapp` 和 `npm run build:weapp:prod` 通过。
- 后端 P0 脚本证明客户和服务商两账号能跑完真实闭环。

## 人工验收路径

| 场景 | 账号 | 入口 | 预期 |
|------|------|------|------|
| 客户吊运 | `13800000004` | 我要吊运 | 进入客户首页，可发布需求和查看订单 |
| 客户误入接单 | `13800000004` | 我要接单 | 进入服务商入驻/审核状态，不展示正式工作台和经营数据 |
| 服务商接单 | `13800000007` | 我要接单 | 进入服务商工作台，可看真实需求、报价、履约和结算入口 |
| 历史链接 | 任意账号 | `dispatch/*`、绑定关系页 | 只显示历史入口暂停提示，并引导回履约订单或资质页 |
