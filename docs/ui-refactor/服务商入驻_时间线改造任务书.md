## 1. 背景与问题

当前页面：[mini-program/src/pages/provider/onboarding/index.tsx](../../mini-program/src/pages/provider/onboarding/index.tsx)、[index.scss](../../mini-program/src/pages/provider/onboarding/index.scss)。

新服务商进入该页时的体感问题：

1. 3 张几乎等权的大卡片（hero + 设备服务能力 + 履约资质 + 基础资料）并列，主次不分。
2. 单屏内 7 个 CTA（查看可补充资料 / 查看账号资料 / 服务商资料 / 设备与资质 / 履约资质认证 / 去完善 / 查看），用户不知从何下手。
3. "审核中" 状态标签重复出现 3 次且都不可操作，传递"哪里都堵着"的负面感。
4. 实名认证是真正的前置条件，却被放在页面最下方。
5. 设备能力和履约资质同时摆出来，对新用户来说是一道额外的选择题。

## 2. 目标 & 非目标

### 2.1 目标（必须达成）

- 入驻页改为"单焦点 Hero + 入驻进度时间线 + 折叠次要入口"三段式结构。
- 任何状态下，**屏幕首屏只突出一个主操作按钮**（其余降级为文字链或次按钮）。
- 用户能在不滚动的情况下，明确看到：当前是第几步 / 一共几步 / 下一步要去哪里。
- 完成步保持视觉静音（灰勾），未来步保持低饱和度，仅当前步高亮。
- 仅修改入驻页本身（`tsx` + `scss`），其它文件不动。

### 2.2 非目标（明确不做）

- 不动后端、不调接口、不改 Redux slice、不改 `roleSummary.ts` 的导出与逻辑。
- 不新增路由、不新增页面、不改 `app.config.ts`。
- 不改其它使用 `resolveProviderCapabilities` 的页面（如 `ProviderWorkbench.tsx`、`settlement/*`）。
- 不引入新的设计 token、不抽公共组件库、不替换字体或颜色体系。
- 不做 i18n（继续硬编码中文，与现有页面一致）。
- 不做骨架屏 / 动画 / 主题切换 / 暗色模式。
- 不补单元测试（该页本身现在就没有测试，保持一致）。
- 不写新的 markdown 文档（除了本任务书已存在）。

## 4. 目标信息架构

自上而下三段：

```
┌─ A. Hero 进度卡（动态文案，1 主 CTA）─────────────────┐
│  入驻进度 N / 4         (右上小字，可选：预计 X 分钟)   │
│  ●●●○ ← 4 段进度条                                     │
│                                                          │
│  {dynamicTitle}        ← 单行大标题，跟随状态           │
│  {dynamicDesc}         ← 一句话说明                     │
│                                                          │
│  [ {primaryCtaText} ]  ← 唯一主按钮（白底蓝字）         │
│  次按钮：仅在"已通过工作台"时出现"查看账号资料"        │
└────────────────────────────────────────────────────────┘

┌─ B. 入驻清单（时间线，非卡片堆叠）──────────────────┐
│  ✓  实名认证            已完成                          │
│  ✓  服务商资料          已完成                          │
│  ●  设备与资质          进行中    ›  ← 当前步带 chevron│
│  ○  平台审核            待提交                          │
└────────────────────────────────────────────────────────┘

┌─ C. 更多入口（次级，文字链分组）────────────────────┐
│  · 履约资质（可后续补充）          ›                   │
│  · 账号资料                         ›                   │
└────────────────────────────────────────────────────────┘
```

视觉权重：A（最重，渐变蓝）> B（中，白底）> C（最轻，无卡片背景，仅分割线）。

## 5. 状态机（不要新增字段，全部从现有 capabilities 派生）

执行者**禁止**修改 `roleSummary.ts`。所有派生计算都写在入驻页文件内的局部纯函数里。

### 5.1 4 步定义与状态来源

| Step | 标题 | 副标题 | 完成判定 | 当前步判定（前序完成且自身未完成） |
|------|------|---------|-----------|-------------------|
| 1 | 实名认证 | 账号实名是服务商审核的基础 | `user.id_verified` ∈ `{'approved','verified'}` | `user.id_verified` ∈ `{'unverified','rejected', undefined, null}` |
| 2 | 服务商资料 | 维护联系人与服务范围 | `capabilities.assetStatus !== 'none'` | Step 1 已完成 且 `assetStatus === 'none'` |
| 3 | 设备与资质 | 上传证照、适航与保险 | `capabilities.assetStatus === 'approved'` 或 `capabilities.canPublishSupply` | Step 2 已完成 且 `assetStatus ∈ {'pending_review','rejected','suspended'}` |
| 4 | 平台审核 | 审核通过后即可正式接单 | `capabilities.canUseWorkbench === true` | Step 3 已完成 且 `assetStatus !== 'approved'` |

特殊状态文案（覆盖默认"已完成 / 进行中 / 待提交"）：

- `id_verified === 'pending'` → Step 1 显示 "审核中"，tone=orange，**不算完成，不算当前**（即跳到 Step 2 之前需等它过审；Hero CTA 为 "查看实名认证进度"，点击进 verification 页）。
- `id_verified === 'rejected'` → Step 1 显示 "需补充"，tone=red，CTA "重新提交实名"。
- `assetStatus === 'pending_review'` → Step 3 显示 "审核中"，tone=orange，Hero CTA "查看可补充资料"。
- `assetStatus === 'rejected'` 或 `'suspended'` → Step 3 显示 "需补充"，tone=red，Hero CTA "补充服务商资料"。

### 5.2 当前步规则

按 Step 1 → 4 顺序找**第一个未完成**的步骤；如果它处于"审核中 / 需补充"等过渡态，那它就是当前步，对应 chevron 显示。如果四步全部完成 → Hero 切换为"已通过"形态，没有"当前步"。

### 5.3 Hero 文案矩阵

按以下优先级匹配，匹配到即采用（与原 `headerCopy` 行为对齐，只是聚焦到"下一步"）：

| 条件（按顺序判断） | label / tone | title | desc | primaryCtaText | onPrimary |
|------|---------|--------|---------|------|------|
| 未登录 `!isAuthenticated` | "待登录" / blue | "登录后开始服务商入驻" | "登录后即可提交服务商和设备资质。" | "去登录" | navigateTo `/pages/auth/login/index?roleMode=provider` |
| `canUseWorkbench === true` | "已通过" / green | "服务商能力已开通" | "你的账号已具备正式接单能力。" | "进入工作台" | `dispatch(setHaulRoleMode('provider'))` + `switchTab('/pages/home/index')` + `syncCustomTabBar(0)` |
| `id_verified === 'pending'` | "审核中" / orange | "实名认证审核中" | "等待实名核验通过后，即可继续提交服务商资料。" | "查看实名认证进度" | navigateTo `/pages/verification/index` |
| `id_verified === 'rejected'` | "需补充" / red | "实名认证未通过" | "请按要求重新提交实名信息。" | "重新提交实名" | navigateTo `/pages/verification/index` |
| Step 1 未完成 | "未开始" / gray | "先完成实名认证" | "实名是服务商审核的基础条件。" | "去实名认证" | navigateTo `/pages/verification/index` |
| Step 2 当前步（assetStatus='none'） | "未开始" / gray | "完善服务商资料" | "填写联系人、服务范围与基础履约信息。" | "完善服务商资料" | navigateTo `/pages/profile/owner/index` |
| Step 3 当前步且 `assetStatus='pending_review'` | "审核中" / orange | "服务商资质审核中" | "审核通过后即可进入正式工作台。" | "查看可补充资料" | navigateTo `/pages/profile/drones/index` |
| Step 3 当前步且 `assetStatus ∈ {'rejected','suspended'}` | "需补充" / red | "服务商资质需补充" | "请补充被驳回或暂停的资料后重新提交。" | "补充服务商资料" | navigateTo `/pages/profile/drones/index` |

进度数 N：当前已完成的 Step 数（0–4）。审核中态计入 N 之前的已完成数，不计入自身。

### 5.4 次按钮规则

只有当 `canUseWorkbench === true` 时显示次按钮 "查看账号资料"（避免新用户首屏 CTA 过多）。其它情况下，Hero 内**只保留 1 个主按钮**，不出现次按钮。
